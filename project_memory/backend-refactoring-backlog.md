# Бэклог рефакторинга бэкенда

Найдено при разборе бэка в августе 2026. В тот заход сделали только атомизацию
методов и ruff (коммиты `518ede4`, `8b9a161`); всё перечисленное ниже отложено
осознанно. Слои `api → services → db` разделены нормально — общую структуру
переделывать не нужно, это точечные правки.

Порядок внутри разделов — по убыванию отдачи.

## Архитектура

### 1. Доменные исключения вместо `HTTPException` в сервисах
`campaign_service.get_campaign`, `recipient_service.get_recipient`,
`recipient_service.add_recipients`, `config_service.get_config` бросают
`HTTPException` — то есть сервисный слой знает про HTTP.

Из-за этого сервисы нельзя переиспользовать из воркеров, CLI или скриптов:
там `HTTPException` бессмысленен. Завести `NotFoundError` / `ValidationError`
в `app/core/` и маппить их в обработчике в `app/main.py` — там уже есть
инфраструктура для конвертов ошибок.

### 2. Единая транзакция на запрос
Сейчас каждый сервис коммитит сам (`create_campaign`, `set_status`,
`add_recipients`, `import_recipients`). Две операции нельзя объединить в одну
транзакцию, а частичный сбой оставляет БД в промежуточном состоянии.

Сервисы должны делать `flush()`, а `commit()` — происходить на границе запроса
в зависимости `get_db` (`app/db/session.py`): коммит при успехе, откат при
исключении. Воркеры продолжают коммитить сами — у них своя сессия на поток.

### 3. N+1 в списке кампаний
`GET /api/campaigns` (`app/api/campaigns.py`) для каждой кампании вызывает
`campaign_service.get_progress`, а тот делает отдельный запрос — итого 1+N.
На 15 кампаниях это 16 запросов вместо одного.

Лечится одним `GROUP BY campaign_id, status` по всем кампаниям сразу.

Там же: `recipient_service.validate_campaign_ready` в цикле обращается к
`recipient.configs`, каждый раз доставая конфиги ленивой загрузкой →
`selectinload(Recipient.configs)`.

### 4. Общий базовый класс воркеров
`Worker` и `ConfigWorker` после рефакторинга структурно одинаковы: `start` /
`stop` / `_loop` / `_tick` / `IDLE_INTERVAL` / глушение ошибок — всё дублируется.
Просится `BackgroundWorker` с абстрактным `_tick()`; наследники оставляют
только свою логику. Специально сделали их симметричными, чтобы это вынесение
было механическим.

### 5. Сессия на конфиг вместо сессии на батч
`ConfigWorker._tick` открывает одну сессию на весь проход по очереди, а внутри
идут медленные SSH-вызовы (десятки секунд на конфиг). Транзакция живёт всё это
время — на SQLite это риск блокировок для HTTP-запросов.

Нужна сессия на конфиг: короткая транзакция вокруг каждого перехода статуса.

### 6. `CampaignTotals` вместо голого `dict`
`campaign_service.get_progress` возвращает `dict`, `CampaignRead.totals` описан
как `dict | None`. В OpenAPI это `object` без полей, поэтому на фронте типы
приходится дописывать руками. Завести pydantic-модель с полями
`sent/failed/pending/total` — типы поедут на фронт сами.

### 7. `deps.get_worker` больше не используется
После удаления неиспользованной зависимости из `start_campaign` функция
`get_worker` в `app/api/deps.py` осталась без вызовов. Решить: убрать или
оставить как задокументированный доступ к воркеру (сейчас оставлена).

## Инфраструктура

### 8. SQLAlchemy 2.0 style
Везде используется legacy-API `db.query(...)`. В SQLAlchemy 2.0 канонично
`select()` + `db.scalars()`; `Query` объявлен legacy. Миграция механическая,
но затрагивает все сервисы и воркеры — поэтому отдельным заходом.

### 9. Фабрика `create_app()`
`app/main.py` собирает приложение на уровне модуля: `FastAPI(...)`,
`add_middleware`, регистрация обработчиков и роутеров — всё побочными
эффектами импорта. Мешает поднять два экземпляра с разными настройками и
тестировать. Обернуть в `create_app()`.

### 10. Alembic вместо `Base.metadata.create_all`
Схема создаётся в `lifespan`. Любая правка модели требует пересоздания БД
(`make remake_db`) с потерей данных. Пока приложение локальное — терпимо;
при первом же боевом стенде понадобятся миграции.

### 11. `seed_campaigns.py` из корня в `scripts/`
Скрипт сидинга лежит в корне репозитория рядом с конфигами.

### 12. Тесты
Тестов нет вообще. Отложены осознанно. Кандидаты, которые тестируются без БД и
без сети (все — чистые функции после рефакторинга):
`import_service.parse_recipients_text`, `import_service._parse_line`,
`import_service._new_config_names`, `recipient_service.validate_email`,
`mail_sender.MailSender._is_temporary`, `mail_sender.MailSender._format_to`,
`config_generator._config_filename`,
`config_generator.SshVpnConfigSource._build_curl_command`, `main._cors_origins`.

Дальше — `Worker`/`ConfigWorker` с подменённым отправителем и источником:
после разбиения `_finish_campaign` и `_process_campaign` вызываются напрямую.

## Безопасность

### 13. SSH принимает любой host key
`app/services/config_generator.py`, `SshVpnConfigSource._connect`:
`paramiko.AutoAddPolicy()` принимает ключ любого сервера, который ответит на
подключение. Это отключённая защита от MITM: подменивший адрес получит и пароль
SSH, и пароль панели VPN. Ruff-правило `S507` (сейчас не включено).

Нужен `known_hosts` или пиннинг отпечатка в настройках.

### 14. Пароль панели VPN виден в списке процессов
Там же, `_build_curl_command`: логин и пароль уезжают аргументом командной
строки (`curl -u user:password`). На VPN-сервере их видит в `ps aux` любой
пользователь, и они оседают в истории/аудите процессов.

Передавать через stdin (`curl -K -`) или через `--netrc` на сервере.

Смежное (уже отмечено в `AGENTS.md` как недоделка): SSH-доступ только по
паролю, авторизации по ключу нет.

## Прочее

### 15. `pyyaml` в `Pipfile` не используется
Остался от удалённого легаси-CLI, в `app/` не импортируется нигде
(проверено `grep`). Отмечено и в `AGENTS.md`.

### 16. `RUF001/RUF002/RUF003` включать не надо
Правила ambiguous-unicode дают ~105 ложных срабатываний на кириллице
в комментариях и докстрингах (русские «а», «с», «е» похожи на латинские).
Причина записана комментарием в `pyproject.toml`, чтобы не включили заново.

### 17. Формат исходников держит форматтер
`ruff format` теперь применён ко всей кодовой базе при `line-length = 100`.
Дальше стиль держится сам — руками выравнивать переносы не нужно, достаточно
`make format`. Отдельно: правило `PLE2515` ловит невидимые символы в исходниках
(NBSP/ZWSP/BOM) — оно уже сработало один раз по делу в `import_service.py`.
